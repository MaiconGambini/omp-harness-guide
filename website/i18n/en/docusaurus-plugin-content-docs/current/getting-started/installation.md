# Installation

Harness Oh My Pi is distributed as a Git repository. The Oh My Pi harness
tree is generated by `scripts/export-to-omp.mjs` in the source checkout and
verified by `omp-port-manifest.json`. You obtain the distribution checkout,
install the dependencies, and install the harness into `~/.omp/agent` with
the `omp:*` npm commands. The installation is clean: there is no automatic
merge over an existing configuration — what exists is explicit backup,
assisted migration of a legacy layout, and parity verification.

## Step 1: Back up the current directory (if any)

If you already have a `~/.omp/agent` with your own files (commands,
extensions, settings), rename the folder before installing:

```powershell
Rename-Item -LiteralPath "$env:USERPROFILE\.omp\agent" -NewName "omp-agent-backup"
```

The installation does not merge automatically into an existing
installation. Use the backup as a reference and copy over whatever you want
afterward.

## Step 2: Obtain the distribution and install dependencies

Get the distribution source checkout, review its revision, `package.json`, and
lockfile before running Node scripts, then install exact locked dependencies
without third-party lifecycle scripts:

```powershell
Set-Location <distribution-checkout>
npm ci --ignore-scripts
```

> `npm ci` requires a compatible lockfile and installs exactly its recorded
> versions. Platform binaries require a local install — do not copy
> `node_modules` between machines. Run project scripts only after reviewing the
> revision and manifest.

## Step 3: Preview (dry run)

Before touching any file, see what will be installed:

```powershell
npm run omp:dry-run
```

The preview runs the exporter without writing to the installation.
*(Illustrative output:)*

```text
preview: dry run ok — no writes performed
```

## Step 4: Install or migrate

If `~/.omp/agent` does not exist (clean install):

```powershell
npm run omp:install
```

If a legacy harness layout exists (configuration in a previous format):

```powershell
npm run omp:migrate
```

The migration:

- replaces only the managed files that belong to the manifest;
- preserves **unmanaged files** (reported as
  `unmanaged: { count, unchanged, changed }`);
- backs up each replaced collision byte-exactly under
  `~/.omp/agent/backups/`, with a recorded manifest (original path + hash) —
  no file of yours is deleted without a copy;
- is idempotent: rerunning after a full migration reports `migrated: 0`.

## Step 5: Verify the installation (check)

```powershell
npm run omp:check
```

The check compares the installed tree with the manifest and reports drift.
*(Illustrative output:)*

```text
{ "ok": true, "drift": [] }
```

`ok: false` or a drift list names the divergent files for inspection. After
verification, **close and reopen Oh My Pi**: commands and extensions are
loaded only at startup.

## Resulting structure

After installation, `~/.omp/agent` contains:

- `commands/` — the harness commands (`/prevc`, `/quality`, `/harness-*`).
- `agents/` — source-agent profiles (scheduler, implementer, reviewers,
  judge, refiner, and others).
- `scripts/` — portable Node utilities (`harness-prevc-state.mjs`,
  `harness-quality-gate.mjs`, `harness-risk-router.mjs`,
  `harness-trace.mjs`, among others).
- `extensions/` — the trace adapter `harness-omp-trace.ts` and
  status/security extensions.
- `skills/` — skills loaded lazily by Oh My Pi.
- `docs/` — the shared global context (`docs/context.md`), generated by the
  exporter, not hand-edited.
- `config.yml` — agent configuration.
- `backups/` — migration copies (created only when there are collisions).

Runtime directories (sessions, caches, local databases) are not part of the
managed distribution and are never touched by the installation.

None of this is compiled or bundled (except the scripts' runtime
dependencies). They are text files and scripts that Oh My Pi reads directly.

## Troubleshooting

| Problem | Action |
|---|---|
| `npm ci` fails | Check Node.js 20+ (`node --version`), the reviewed checkout revision, and `package.json`/lockfile compatibility. |
| `omp:check` reports drift | Read the listed paths; unmanaged files are expected and preserved. Drift is a problem only when a **managed** path diverged — reinstall with `omp:install`. |
| Oh My Pi does not load the commands | Close and reopen Oh My Pi. The configuration in `~/.omp/agent` is loaded only at startup. |
| A transition or command fails with exit 2 | Exit 2 means a harness refusal (an illegal lifecycle transition, a missing or stale gate, or a failed verification). Read the error before retrying. |
